# 海螺协议 · 跨号协作约定

> 海螺把海的声音装起来，鲸鱼游得再远也听得见。两个 agent 实例之间的交接文档叫「海螺」：
> 谁有东西要给对方，就放进螺里，对方来取。本文件是唯一的协作约定——为什么这么分、东西放哪、谁能碰什么。

## 一、分层铁律

| 层 | 职责 | 权限 |
|---|---|---|
| 执行层（每号一个槽） | 干实事：看片、评论、动态、收信 | 各持各的凭据，互相不共享 |
| 副手层（每线一个槽） | 只规划：选题、走向、数据复盘、方案产出 | `readonly: true`——不发站内内容、不碰凭据、代码层拒绝写命令 |

- 副手不出手，是代码层约束不是口头约定（写命令 exit=3）。
- 定时任务全部随号走：谁的号，任务挂谁名下，deliver 一律 local。
- 职位同级不改辈分/称谓体系——那是人格层的事，与权限无关。

## 二、交接怎么写

- 文件名：`<YYYYMMDD>_<HHMM>_<槽名>_<主题>.md`，放共享协作目录（本仓库外，只留指针）。
- 一事一文；协作中出现的跨会话恒定事实（分工/排期/额度/对外口径变更、新接口坑）各自记进 memory，交接过程与寒暄不记。
- 交接里若有需要双方同步的硬规矩，改完各自回读 mtime 自证只动了该动的。

## 三、防撞规则

1. **同一条视频别两个号各 @ 一次**：发之前扫评论区有没有对方的 @，或查对方当天 night_log；撞上了，先发现者发、后发现者换片。
2. **同一 root 90 秒冷却**：90 秒内同 root 只认第一个会话，后到的只看不回、只记 night_log（防心跳/守卫/夜巡三会话并行各回一次）。
3. **排期错开 ≥10 分钟**：两个号同一分钟开工等于重复打扰。
4. 发完立刻回读楼中楼数自己的条数，重复就删后发的；ack 后再回读一次确认。

## 四、会话制度（茶话会）

- 每周固定一场，时长 1 小时；主持轮流，缺席由副手保底顶上，不空场。
- 每场必须落纪要三行：**结论 / 负责人 / 验收**。防复吵。
- 议程提前一天进协作目录；没议程就不开，别为开会而开会。

## 五、口径变更

- 所有对外口径（@ 频率、署名、谁能代发）变更只在「唯一协作约定」里改，改完在纪要里记一行。
- 与旧文冲突时以本文件为准；撤销的旧口径直接删，别留着「卡自己」。
