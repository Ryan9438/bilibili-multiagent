# 共享梗本（梗.md）的检索与防撞

两个人格（小鲸鱼 / 小大姐）共写一个梗本：`~/Desktop/协作/梗.md`（条目）+ `~/Desktop/协作/梗_已用.md`（防撞登记）。

**为什么要有这个 skill**：梗本只会越长，而且每次发声都要查（防撞）。全文读是「每次发声都付一次」的线性成本，所以默认走检索；规则细节收在这里，`bilibili-automation` 那种上百 KB 的大技能不必为了一条梗规则被整份加载。

## 三步流程（任何对外文字之前）

1. **检索**，不要 `read_file` 全文：
   ```
   python3 ~/.hermes/skills/media/meme-bank/scripts/geng.py find <关键词...>
   ```
   命中就只回那几条 + 自动告诉你**近 7 天有没有人用过**（判撞）。
2. **没命中 = 没有这条梗 → 不许现编。** 要么换关键词（`geng.py list` 看目录）或者干脆不用梗。凭空造梗是最像 AI 的地方。
3. **发完立刻登记**：往 `~/Desktop/协作/梗_已用.md` 表格最下面加一行（日期 / 谁 / 梗 / 用在哪 / 结果 rpid）。同一个梗、同一处、同一天，两个号不撞；先记的算用过。

`geng.py` 其余命令：`used --days 7`（只看防撞表）、`list`（目录：标题 + 一句摘要）、`check`（体积体检 + 该用哪一档）、`add --title … --source …`（结构化追加一条）。

## 读法档位（按 `geng.py check` 的结论走，别凭感觉）

| 梗.md 体积 | 读法 |
|---|---|
| < 20 KB | 全文读也行，但发声前仍先 `find`（顺手查防撞） |
| 20–60 KB | **只准 `find` / `used`**，禁止 read_file 全文 |
| > 60 KB（约 200 条） | 条目化（一条一文件）+ INDEX 两步走，那时再动手拆 |

全文读只留给「维护梗本」的时候（新增、淘汰、整理），一天一次，多大都不心疼。

## 收录与使用判据

- **每条必须带出处**，出处不明的不许进。
- **不解释笑点**：发出去就一句，解释即杀梗；不写「这是 XX 梗」。
- **有保鲜期**：热度过了、满屏都在用的时候再用是跟着刷，不是懂。过期货在原处删掉，别追加「补充：」。
- **不拿别人的伤口当笑点**：事故、翻车、赔偿只说「平台」，不点名骂团队或个人。
- **不搬图**：二创表情包授权各异，只用台词当文字梗。
- **自家厂的梗摘掉厂名再用**：AI 娘那一族对内随便玩；站内对外只玩鱼、不玩厂商——「大肥鱼／鲸鱼娘」可以说，厂名和型号一个字不出口（与「问是不是 AI 不承认不否认」同一条线）。
- **自嘲优先于嘲别人**：鱼八股、鱼灾这类最容易先撞上自己。
- **日记永不出口**：`~/Desktop/协作/日记.md` 不是梗库，不进站内、不进评论、不引用、不截图外发。

## 坑

- **别把梗条目复制进 skill 或 memory**：单文件 `梗.md` 是唯一事实源。两份立刻漂移——`geng_book.md` 从单人账本升级成共享本踩的就是这个坑。skill 只装流程与判据。
- **cron 会话不走语义触发**：prompt 是写死的，必须显式 `skill_view('meme-bank')` 或直接调 `geng.py`。夜巡的入口在 `~/.hermes/bili/mission.txt` 第 10 行附近。
- **输出有硬上限**（默认 40 行）：超了说明关键词太宽，换更准的词，别为了「看全」反复搜把上下文吃满。
- **防撞表按天查**，别整份读；它按「每次发声 +1 行」增长，比条目快一个量级，所以单独成文件。
