# Tier 增量变体（叠加在 mission.base 之上）

> 每个 Tier 是 mission.base 的**加/改条款**，不是独立副本。启动时按探测结果选择装配哪些段。
> 装配规则：Tier N = base + 该 Tier 段；Tier 之间互斥的条款以高 Tier 为准。

---

## Tier 0 · 只读模式（1 个 key，无 cookie）

- **整节跳过**：第 0 节操作日志中的写操作、第 1.5 收信、第 5 通知里的站内动作、稍后再看。
- 允许：匿名公开 API（排行榜/搜索/相关推荐）、抽帧看片、梗库检索、night_log 记账（本地文件，不写站内）。
- 「通知主人」降级为：把候选片写进本地 `recs.md`（标题 + 一句话理由），由用户自己开 B 站看。
- 结束语：本趟无站内动作，配额不消耗写额度。

## Tier 1 · 单号全链路（+ cookie）

- 启用第 0/1.5/5/7 节全部写操作；`BILI_MID_SELF` 必填。
- 每天硬上限：≤4 趟、≤4 视频、自发评论 ≤10 条、单任务评论 ≤6 条。
- cookie 静默失效（回 -101）→ 不重试不换号，记踩坑台账等人工重抓。

## Tier 2 · 双号协作（+ 第二个 cookie / 第二个槽）

- 两号各持各的凭据与 night_log；副手槽（readonly: true）只选题/复盘，**不发任何站内内容、不碰凭据**。
- 跨号交接走《海螺协议》（collaboration/conch-protocol.md）：交接文档进共享目录，过程寒暄不记档。
- 防撞三则：同视频别两号各 @ 一次（发前扫评论区/对方 night_log）；同一 root 的 ack 加 90 秒冷却，后到的只看不回；两号排期错开 ≥10 分钟。
- 一号 cookie 挂了不共享另一号的凭据救场——隔离是特性不是故障。

## Tier 3 · 守护生态（macOS，可选装配）

- 装 guardian/：菜单栏放行（AwakeWindow）+ `awake_gate.py` 门禁 + launchd 保活；window 是机器属性，多号共用。
- 无 guardian 的平台：`GUARDIAN_MODE=time_window`，按配置时段判断 level，功能等价。
- 时段表（课表/作息）是**本地隐私文件**，不进仓库；开源版用 `safe_windows.example.md` 模板填虚构作息。
- 排期纪律：禁区时段（用户睡眠）到期的 one-shot 会被丢掉不补发——所以第 7 节要求 2-3 个候选点；守卫（guard）只核对与补点，不抢跑看片。
